설계

브레인스토밍 → 설계 문서 → 구현 계획

새 서브시스템이라 정식 절차로 진행: TMDB 연동 방식(ID 입력→자동조회), 좌석 등급(전부 STANDARD로 생성), CRUD 범위(생성+조회만) 세 가지를 먼저 결정하고 설계 문서 작성. 그 다음 19개 태스크짜리 구현 계획 문서로 쪼갬 — 2026-09-15-admin-tmdb-design.md, 2026-09-15-admin-tmdb.md(plans).

구현

Movie — TMDB 연동

TmdbClient로 TMDB API 두 번 호출(영화 상세 + 관람등급), record/@JsonProperty/@JsonIgnoreProperties 처음 사용. MovieService.registerMovie()는 직접 짜보다 막혀서(new Movie() 빈 생성자로 시도 → setter 없음 재확인) 코드 받아서 완성.

오타thdbId → tmdbId (Movie 엔티티, DTO 두 군데서 반복)
구현

ADMIN 권한 체크 배선

JwtAuthenticationFilter가 role을 USER로 하드코딩해뒀던 걸 발견 — JwtTokenProvider.getRole() 추가해서 토큰의 실제 role을 읽도록 수정. SecurityConfig에 @EnableMethodSecurity 추가해서 @PreAuthorize("hasRole('ADMIN')")가 실제로 작동하게 함.

전환

MySQL → PostgreSQL 통째로 교체

포트폴리오 스펙 다양화 목적으로 중간에 DB를 바꾸기로 함. build.gradle.kts 드라이버 교체, application.yaml URL/포트(3306→5432) 변경, IntelliJ Run Configuration에 DB_USERNAME=postgres 추가. 새 DB라 기존 테스트 데이터(회원 등)가 다 날아가서 회원가입·ADMIN 승격을 처음부터 다시 함.

구현

Screen/Seat — 좌석 자동생성

ScreenService.createScreen()에서 중첩 for문 + (char)('A'+row)로 행/열 개수만큼 좌석을 일괄 생성하는 로직. 처음 써보는 문자→숫자 변환, saveAll().

오타PRIMIUM → PREMIUM, rowlabel → rowLabel (절반만 리네임해서 자기 자신에게 대입하는 조용한 버그 — 컴파일은 됐지만 값이 항상 null이 되는 케이스였음)
구현

Showtime — endTime 자동계산

ShowtimeService.createShowtime(): movieId/screenId로 조회 후 startTime.plusMinutes(movie.getRunningTime())로 종료시간 자동 계산. 이 부분은 여러 번 시도했지만 계속 막혀서 결국 전체 코드를 받아 타이핑.

위치Showtime 엔티티가 com.dw.movie.auth.showtime에 잘못 생성 → com.dw.movie.showtime로 이동 (Refactor)
누락생성자에서 createAt 초기화를 빼먹어서 계속 null로 남는 버그 — 추가해서 해결
디버깅

Postman 인증 헤더, 한참 헤맴

최종 통합 테스트 중 401 인증이 필요합니다가 계속 남. 원인은 Authorization 헤더에 Bearer 뒤 공백 위치가 밀려서 Beare r<토큰>처럼 깨져있던 것 — Headers 탭 수동 입력 대신 Postman의 "Authorization → Bearer Token" 전용 탭으로 바꿔서 해결. 그 다음엔 Body를 안 채워서 tmdbId: null 에러 → Body에 JSON 채워서 해결.
